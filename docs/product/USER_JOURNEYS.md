# Product Completion | Journeys, Not Features

Use these journeys to decide what to build and honestly call complete. Do not substitute a feature list or green-test count.

| Journey | User-visible success | Common false completion |
|---|---|---|
| J1 one occurrence | Source + intent -> best supported audio or honest scoped status | requires another episode or released reference |
| J2 independent availability | known released same recording recognized, unique unavailable edits kept | all OP/ED suppressed, or partial match called whole EXACT |
| J3 candidate selection | target retained, unwanted sound reasonably reduced, uncertainty visible | one proxy score treated as truth |
| J4 listening product | valid audio, usable loudness, tags, artwork policy, atomic export | bare isolated stem with lost tags |
| J5 memory and evolution | Asset identity, CurrentBest, revision lineage, alternate representation | latest output overwrites valid older one |
| J6 restart/repair | reuse, interrupted job recovery, missing-output regeneration | re-inference after tag-only change |
| J7 storage/autonomy | owned cache/scratch cleaned safely without human housekeeping | arbitrary delete with no lineage |
| J8 user result | READY -> PROCESSING -> SESSION COMPLETE reflects actual published/held/reused/failed statuses | UI says success where no audio was published |
| J9 field survival | representative real-use behavior resists consequential silent-wrong cases | synthetic unit tests substitute for actual package |
| J10 work music map (grows with use; never gates J1) | music found by scene, episode or cue: each cue lists the scenes it played in, each episode its music and what is still unresolved | a flat folder of files; renaming loses the scene history |

## Completion states
- Supported journey complete **at a specified source/target scope**.
- Shared Product services complete for normal local use across currently supported journeys.
- Expansion-ready for another concrete target without redoing identity/publication.
- Frontier work can remain open indefinitely and still allow a useful complete supported Product.

Prioritization is dynamic: ask which work most improves the journey that matters, which capability is a shared concrete lever, and what can run independently. A narrower success does not justify redefining the scope *after* evaluation.

## Outcomes stay distinct
Zero output is a correct result when no wanted music exists; LSS never generates a cue to raise a count. Absent, not found, unresolved, failed (including a cue missed because separation failed, never recorded as "no BGM"), held and unsuitable to publish are different states, and an unknown is never shown as absent.

## Optional references do not gate J1
The absence of a soundtrack, internet, recurrence or official name may reduce quality, not legitimacy of useful single-occurrence Product operation.
